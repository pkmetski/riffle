Backward scroll across a short part-title resource in continuous mode surfaced THREE distinct field bugs in "Taking Charge of ADHD" (2026-08-02..04). All fixed on branch pkmetski/continuous-scroll-stuck-title-page; verified by ContinuousChapterBoundaryHarnessTest (synthetic long-chapter | tiny-part-title | long-chapter EPUB via StubAbsServer epubBytesProvider).

1. **Prepend/evict ping-pong (blank screen, Aug 2).** ShiftBackward prepends prev chapter; compensating scroll change re-runs decide with intent consumed; tiny part title leaves viewport midpoint at topIndex+2 > chaptersBehind → index-based ShiftForward evicts the fresh prepend 130 ms later, clamps scrollY to 0, repeat. Fix: geometric guard in `ChapterWindowManager.decide` — ShiftForward only when `scrollY - firstChapterHeight >= viewportHeight/2` (exempt on atBottomOfLoadedWindow). Old PR-#594 test pinning the oscillation was flipped to Hold.

2. **Momentum overshoot (jump deep into prev chapter, Aug 3).** On device each MotionEvent is its own main-loop message → prepend fires MID-drag; NSV's ACTION_UP release fling composes scroller DELTAS with the prepend compensation and carries the reader ~9k px past the boundary. Fix: `ContinuousReaderView.fling()` swallows the fling when `controller.suppressGestureFling` (gesture already consumed by a prepend; cleared on DOWN); plus unconditional `port.abortFling()` in the ShiftBackward branch. Test seam: gesture MUST be dispatched event-by-event (separate onActivity per MotionEvent) — atomic one-block dispatch defers the posted prepend past UP and never exercises the swallow.

3. **Placeholder stacking (solid white page, Aug 4).** Each backward pull prepends another screen-sized blank placeholder while the previous one is still loading (real chapters take seconds on device; stub measures in ~100ms which is why emulator missed it). Fix: `topChapterStillPlaceholder` param on decide + `prependAwaitingMeasure` flag in controller (cleared on measure/removeTop/openWindowAt) — one unmeasured prepend at a time.

4. **Blank-drag teleport (abrupt jump, Aug 5).** Pixels dragged through the unmeasured placeholder resolve to never-seen content when the measure's compensating scrollBy lands (distance-from-boundary is preserved, so blank-dragged px map deep into the prev chapter). Fix: scroll FLOOR while `prependAwaitingMeasure` — `ContinuousReaderView.onOverScrolled` clamps scrollY to the placeholder's bottom edge (`ContinuousPositionTracker.backwardPrependScrollFloor`), holding the reader AT the boundary until the chapter renders; compensations scroll below the floor so they pass unclamped.

5. **Measured ≠ painted (the residual "abrupt jump"/white, Aug 5).** Layout height lands ~300 ms after a prepend even for a 33k-px chapter, but Chromium rasterization takes seconds on weak GPUs — lifting the floor at measure time let the NEXT flick (new gesture, nothing swallowed) legitimately fling ~13k px into a measured-but-unpainted region: solid white, fills in late. Reproduced on own AVD (landed sY=18443 = 56% into ch06, 10+s white). Fix: paint gate — floor holds until `WebView.postVisualStateCallback` confirms the draw (`ChapterWebView.onCurrentContentPainted`, loadToken-guarded) or a 5 s timeout; also feeds the one-prepend-at-a-time gate.

6. **Behind-buffer fling teleport (the "still happens" report, Aug 5 round 2).** All prepend gates only cover freshly-PREPENDED chapters; when the previous chapter is already in the window (behind buffer at open, or after a first crossing) a backward fling is unbounded — reproduced: one fling from the Part II page → 4 viewports deep into unpainted ch06. Fix: `ContinuousPositionTracker.backwardFlingFloor` — a backward fling lands at most one page (0.9·vh) past the chapter boundary above its starting chapter (sub-half-viewport part titles folded into the boundary). ANCHOR ON THE VIEWPORT MIDPOINT (not top — the top routinely sits in the previous slot while the user reads the next chapter) and capture the floor at ACTION_DOWN (by fling time the drag has already crossed the slot). Armed in `ContinuousReaderView.fling(velocityY<0)`, enforced by the onOverScrolled clamp, cleared on DOWN + navigateTo.

6b. **Unbounded boundary fold ("Free Excerpt" edition, Aug 5 round 3).** Back matter is often a RUN of sub-half-viewport resources (about-author, publisher, promo); the fling floor's boundary fold walked the whole run, so one pull from the excerpt page skipped them all into the index. Fix: fold cap — stop folding once the folded run exceeds viewport/2. Every backward pull now travels ≤ ~1–2.5 viewports. NOTE: user's ABS server drops all POSTs (login rate-limit?) from this Mac after repeated login attempts — GETs fine; geometry had to be inferred from the recording.

7. **Stale nav landing yank (found via harness, real papercut).** `navigateTo`'s in-window `port.post { scrollToLoadedChapter }` can execute SECONDS later under main-thread measure storms; the 2.5 s initial-scroll fallback likewise. Both then yank the reader back to the stale nav target mid-scroll. Fix: any touch-down supersedes both (cancels fallback runnable + clears pendingInitialScroll WITHOUT invoking the stale scroll + `inWindowNavSupersededByTouch` flag checked by the posted landing).

Boundary-detent semantics (final): the gesture that crosses a boundary lands AT the boundary (floor holds through measure + paint + until the next gesture); the next gesture continues into painted content but its fling still caps one page past any further boundary.

Harness-test lessons: after `navigateTo` in a leg, ALWAYS wait `isReaderInChapter(fromHref)` before dispatching gestures — the posted landing races the gesture loop and a leftover position can satisfy the destination check with zero swipes, making the late (legitimate) landing look like a yank. Legs after a rebuild-nav also need ~2.6 s settle (INITIAL_SCROLL_FALLBACK_MS) or `pendingInitialScroll` suppresses every shift decision for the whole gesture.

AVD-repro lessons (2026-08-05): (a) CHECK THE READER MODE FIRST — `adb shell dumpsys activity top | grep -oE "ContinuousReaderView|EpubNavigatorFragment"`; I drove Readium paginated mode for an hour believing it was continuous. (b) The API-25 emulator's SwiftShader cannot raster >~80-90k px of stacked WebViews — windows with two adjacent huge chapters (ch05=68k + ch06=33k) stay white FOREVER on the AVD; not reproducible-meaningful there, fine on real GPUs. (c) ABS media-server is Tailscale — bridge with a python TCP proxy on 127.0.0.1:13378 + `adb reverse tcp:13378 tcp:13378`; POST /login from the Mac gets dropped but the app authenticates fine through the bridge. (d) The Harness_Medium_Phone base AVD carries a set-up Riffle library incl. the real ADHD book.

Also: backward *intent* latch (finger-direction from onInterceptTouchEvent ACTION_MOVE; UP/CANCEL only visible via dispatchTouchEvent once intercepted) is retired by an idle-poll watch (150 ms) after UP; the watch runs ONE final maybeShift before dropping the intent — under main-thread contention the clamp's posted shift check can land after retirement and a legit prepend would silently vanish (seen as harness flakes).

Debug infrastructure gotchas: streaming `adb logcat` in parallel with a harness run can kill the adb server mid-run (5+ emulators on this machine); prefer booting an own AVD clone manually, running `ANDROID_SERIAL=… ./gradlew :app:connectedDebugAndroidTest -P…class=…`, then `adb -s $SERIAL logcat -d` AFTER the failure. Or bake diagnostics into the test's failure message (window dump: url:height:top + scrollY) — no adb needed. Match the FULL branch-specific AVD name (`Harness_<branch>_*`) when attaching to the make-managed emulator.
